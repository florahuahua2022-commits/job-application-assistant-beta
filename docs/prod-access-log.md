# 生产访问记录

建立日期：2026-10-25（北京时间，UTC+08:00）。本文件从建立后开始记录，不补写过去的访问，不以推测填补缺失事实。当前没有访问条目；创建本文件不代表已经获得任何生产访问授权。

## 执行规则

1. 每次访问生产数据库之前，必须取得用户对本次具体目的、目标环境和访问范围的明确同意。历史授权、其他任务授权、只读、诊断、预检等名称均不能替代本次明确同意。
2. **先记录，后连接**：取得同意后，先追加授权事件，记录事件 ID、北京时间、目的、用户批准的表/操作范围，以及用户同意的逐字原话和来源。此时只记“已授权，尚未执行”的事实，不填任何读取结果，也不把拟访问表写成实际已读表。记录文件不可写或授权不清楚时，禁止连接。
3. 执行前必须准备好只统计本次已批准查询结果的行数和字节数的方法；不得为了补日志再读取一遍生产数据。无法计量时先停止，说明限制并等待用户决定，不擅自连接。
4. 每个实际连接尝试分别编号，包括重试、只读对比、诊断、迁移预检、经连接池或代理的数据库访问。获准的批次也必须逐次记录，不能用一个笼统条目覆盖未知次数。
5. 每次尝试结束立即追加同一事件 ID 的执行结果：北京时间起止、实际目的/操作、实际读取的表、实际返回行数、基于本次结果计算的大致字节数及计量口径、成功/失败/中断、授权原话或授权事件引用。只记录事实；有测量缺口必须明确写“未记录”，不得编造、估算或补读以凑数字。意外失败导致未记录不构成允许继续访问的例外；先停止、披露并等待用户指示。
6. 字节数应标明口径，例如本次结果字段 UTF-8 字节总和；它是基于实际返回值的近似载荷量，不冒称 PostgreSQL/TLS/连接池网络流量或云账单字节。分别记录各表返回行数；同一行被重复查询要重复计入。多表 join 无法拆分时注明结果集行数和相关表，不捏造逐表数值。
7. 生产日志/控制台查看也需明确批准并单独记录，注明是否确实连接数据库；不把“看过 Render 日志”写成“查过生产表”。若没有数据库查询，表、行数、字节记“不适用”，不能默认记 0。
8. 所有时间使用北京时间，格式 `YYYY-MM-DD HH:mm:ss +08:00`。不得记录密钥、连接串密码、token、用户数据正文；授权原话若含秘密则不落盘，先要求用户给出不含秘密的明确授权。
9. 唯一权威日志的绝对位置为 `D:/Users/Administrator/Documents/job-application-assistant-audit/prod-access-log.md`。它位于仓库与 Codex 工作树目录之外，所有分支和工作目录只使用此文件。仓库内 docs/prod-access-log.md 仅保存规则与位置引用，不追加访问事实，不合并并行账本。每次访问先在权威日志目录原子创建 prod-access-log.lock 独占锁，核对并追加授权事件，再执行并追加实际结果，最后释放自己的锁。文件不可达/不可写、已有锁或有效性不明时禁止访问，不自动删除不明锁。不得以 Git checkout、reset、merge 或旧分支文件覆盖权威账本。更正只追加，不改写历史；另行迁移必须经用户明确批准、暂停访问并锁定、完整保全事实、追加交接记录，再同时更新 AGENTS.md 和所有位置引用。

## 新条目的格式

以下只是字段定义，不是访问事实。未来每次按此追加，无示例访问、无历史补录。

- 授权事件：事件 ID；北京时间；状态“已授权，尚未执行”；目的；目标环境；批准范围；用户同意原话；原话来源。
- 执行结果：事件 ID/尝试编号；北京时间起止；目的与实际操作；实际读取表；实际返回行数（按查询/表或注明 join 口径）；实际结果的大致字节数和计量方法；成功/失败/中断；授权原话或同 ID 授权事件引用；限制/异常。
- 更正事件：事件 ID；北京时间；被更正事件；更正事实；依据。
