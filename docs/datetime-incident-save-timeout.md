# 保存等待期限修订（相对 b7733fd）

## 实施范围

- 只调整现有六个保存入口：主资料表单、申请内资料编辑、识别联系信息、职位新建/编辑共用表单、已保存职位编辑、申请内公司/职位编辑。
- 共用 saveResponse 默认期限从 30 秒改为 90 秒。一个总期限覆盖请求和 JSON 正文读取，不在收到响应头后重新计时。
- 点击后相邻状态为“正在保存…”，8 秒后为“正在确认保存，免费服务唤醒可能需要约一分钟，请稍候。”。
- 成功、失败、超时均清除两个定时器；慢提示回调检查用户、入口/申请键和请求序号。
- 原有按钮禁用、输入保留、错误持续显示、切换申请保护、确认成功后全局数据更新保持不变。POST 超时仍进入“结果待确认”，不自动解锁或重发；PATCH/PUT 仍可手动重试。
- 不添加预热请求、读取、轮询、依赖或 CI 触发条件；不修改后端、生产配置和其他分支。

## 验证

- RED：旧实现下共用函数测试 7 项中 3 项失败，两个界面测试均失败。
- GREEN：Node 24.22.1，完整前端单元测试 68/68；Playwright 两个界面测试 2/2；前端生产构建通过。
- 假时钟验证 7,999 ms 仍是中性提示、8,000 ms 切换；60 秒响应仍成功；89,999 ms 尚未超时、90 秒后终止；响应头后读正文也共享总期限。
- 界面时钟先暂停，再显式推进；不实际等待 8/60/90 秒。既有错误、手动重试、POST 结果待确认及跨申请迟到回调测试保留。
- 复用 PR #39 的现有 CI：前端单元/界面/构建，Python 3.13 两套依赖的完整离线回归及 PostgreSQL 16 清单。提交后的实际 CI 运行链接和结论随交付回复提供。
