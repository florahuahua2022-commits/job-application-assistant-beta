# 阶段三：前端保存失败反馈

基线：`abce39a`；分支：`codex/production-datetime-incident`。本阶段不改后端、生产依赖、生产配置或 AGENTS.md，不开始阶段四。

## 实施范围

- 新增一个共用响应函数 `frontend/app/saveResponse.ts`：接收带 AbortSignal 的请求函数，返回成功数据或失败类别及 HTTP 状态；不返回/打印服务端正文或原始异常。网络错误、非成功状态、无效 JSON、缺少持久化 id、请求或读响应超过30秒均收口；迟到结果不再触发成功处理。
- 接入 `saveProfile`、`saveApplicationProfileDetails`、`saveDetectedContact`、`createApplication`、`updateSavedJob`、`saveApplicationJobIdentity`。其他保存入口不接入。
- 首次提交前同步防重入，等待时禁用对应按钮。每个用户、入口、申请分别记录 pending/error/sequence；主资料及识别入口使用 global 标识，新建使用 new 标识，没有新增草稿 id、输入缓存、持久化或恢复机制。
- 普通失败在按钮旁持续显示「未能确认保存，输入已保留，请重试。」；编辑职位 PATCH 也是普通重试。重试期间保留错误，成功后清除本入口错误并执行原成功分支。
- 仅 POST 新建使用「结果待确认」：除明确422外，失败保守显示「未能确认保存。职位可能已创建，请先检查已保存职位，避免重复新建。」，阻止重复POST，保留当前输入。
- 「检查已保存职位」只调用原有 `refresh()`，不新增 fetch、查询接口或轮询；该原函数也会刷新资料、简历、积分等既有内容。检查后不自动清除待确认、不自动重新POST。
- 识别联系信息自动保存失败时，在原联系信息区域保留识别结果和独立重试按钮，不重新上传简历。

## 422 提交边界核对

仓库当前 POST `/applications` 的422来自请求体 `JobApplicationCreate` 校验，发生在进入创建函数、执行任何 commit 之前。依赖 `get_session` 只提供 Session、不提交，鉴权依赖不写数据库。

创建函数及其调用链没有提交后产生422或把内部异常转换为422的路径。函数内部 `model_validate` 出错属于未处理错误，不是请求校验422。已追踪 job model、CKB、snapshot、job sources、source-aware 重建等调用。

新建接口确实会先提交申请，再提交来源数据；后续 source-aware 重建可能抛400，其他错误可能为500。因此只把明确422视为可直接重试，不把其他状态一概视为未创建。不提供前端能够保证跨刷新/跨设备幂等的承诺。

## 输入及请求隔离

失败时不调用表单 reset、setProfile 或成功重载。没有新增草稿保存或恢复。

原职位编辑面板使用 `options-${selected.id}` / `edit-${selected.id}` 作为key：切换申请会重挂载，丢弃该面板未保存输入，返回后显示该申请已保存数据。本次保留并测试这个行为；其它非受控表单也沿用原行为，不承诺跨切换恢复输入。

错误按原入口/申请记录，切换后不会显示到另一申请。页面请求序号同时保护A→B→A场景。审阅发现保存成功后的 `openApplication` 重载也可能迟到，现把同一用户/请求序号检查延伸到该重载及关联加载的异步状态写入；没有新增读取。旧回调不能重置当前表单或覆盖另一申请的文档、诊断、门禁显示。其他独立加载调用仍使用原行为。

## 依赖与离线测试

- `@playwright/test` 精确固定 **1.64.1**，`playwright` / `playwright-core` 同为 **1.64.1**，传递依赖由 pnpm-lock.yaml 固定。没有改原有运行依赖或后端requirements。
- CI 保留 Node22及 pnpm10，冻结锁文件安装；用项目内CLI执行 `playwright install --with-deps chromium`，只安装与该版本匹配的Chromium。Linux系统包由CI镜像/安装命令提供，不声称系统包完全锁定。
- 本地使用仓库 engines 范围内的 Node **24.22.1**。冻结锁文件安装通过；Node测试 **66 passed**，其中新增共用函数测试5项；真实浏览器界面测试仅 **2 passed**，分别为资料保存及职位保存；前端构建通过。
- UI测试先在旧前端证明两入口等待期间按钮未禁用；保存后迟到重载污染新申请的新增场景也先失败（新申请出现旧文档编辑器），修复后转绿。
- 两个UI入口覆盖网络、422、500、无效JSON、超时、保留输入、持续错误、成功清除、防重入；职位入口另覆盖POST待确认不重发、检查按钮只复用列表刷新、PATCH可重试、申请间错误隔离、A→B→A旧保存回调及迟到重载失效。
- 假时钟推进30秒，不实际等待30秒，不增加生产短超时开关。所有API由合成夹具拦截，外部页面请求阻断；UI配置拒绝真实dotenv文件、清除继承凭据、禁用线上登录配置，不启动后端或数据库。
- 不新增控制台日志，包括HTTP状态码、响应正文、异常对象或任何凭据。状态码仅用于内部决策和测试。
